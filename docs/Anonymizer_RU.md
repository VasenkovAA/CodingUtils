# `anonymizer` — руководство пользователя

`anonymizer` — CLI‑утилита для поиска и обезличивания конфиденциальной информации в исходном коде, текстовых файлах и Jupyter Notebook.
Она умеет:

- находить файлы по директориям, паттернам и исключениям (аналогично `comment_extractor`);
- учитывать `.gitignore`;
- применять **встроенные правила** для поиска ключей API, паролей, персональных данных (PII), системных путей;
- загружать **пользовательские правила** из YAML/JSON;
- извлекать значения из `.env`‑файлов и искать их в проекте;
- динамически подставлять текущее имя пользователя, домашнюю папку, имя хоста и корень проекта;
- обезличивать найденные совпадения тремя способами: замена на плейсхолдер, удаление строки, хеширование;
- обрабатывать Jupyter Notebook (`.ipynb`), включая выводы ячеек и при необходимости метаданные;
- работать в режиме **preview** (показывает, что будет изменено, без изменения файлов);
- применять изменения только при наличии флага `--apply`;
- создавать резервные копии изменяемых файлов;
- экспортировать отчёт о найденных совпадениях в `.txt`, `.json`, `.jsonl`;
- разделять потоки вывода (`--split-streams`) для удобной интеграции с GUI‑обёртками.

## Быстрый старт

### 1) Найти всё, что похоже на секреты, в текущей папке (рекурсивно)
```bash
anonymizer . -r
```

### 2) Только Python-файлы, встроенные правила (credentials, pii)
```bash
anonymizer . -r -p "*.py" --builtin-rules credentials,pii
```

### 3) Посмотреть, что будет заменено (preview), не меняя файлы
```bash
anonymizer . -r --builtin-rules all --preview
```

### 4) Реально заменить найденные секреты на плейсхолдер `[REDACTED]`
```bash
anonymizer . -r --builtin-rules all --mode replace --apply
```

### 5) Удалить строки, содержащие секреты (осторожно!)
```bash
anonymizer . -r --builtin-rules credentials --mode remove-line --preview
# после проверки:
anonymizer . -r --builtin-rules credentials --mode remove-line --apply
```

### 6) Использовать свои правила из файла `rules.yaml`
```bash
anonymizer . -r --rules-file rules.yaml --preview
```

### 7) Искать строки из `.env` файла и заменить их
```bash
anonymizer . -r --env-file .env.prod --mode replace --apply
```

### 8) Заменить системное имя пользователя на `[USER]`
```bash
anonymizer . -r --detect-system --username-placeholder "[USER]" --apply
```

## Командная строка: синтаксис

### Общий вид
```bash
anonymizer [DIRECTORY ...] [OPTIONS]
```

- `DIRECTORY ...` — одна или несколько директорий. Если не указаны — используется текущая (`.`).
- Большинство опций можно комбинировать.
- Поддерживаются флаги `-d/-dr` для управления рекурсией на уровне отдельных директорий (аналогично `comment_extractor`).

### Справка
```bash
anonymizer --help
```

## Режимы работы: поиск / preview / удаление

Утилита может работать в трёх основных сценариях:

### A) Только поиск (по умолчанию)
- Находит совпадения и печатает их в лог (или в stdout при `--split-streams`).
- Файлы не меняются.

```bash
anonymizer src -r --builtin-rules credentials
```

### B) Preview удаления (`--preview`)
- Вычисляет, какие совпадения **были бы заменены** (или строки удалены).
- **Файлы не меняются.**
- Полезно для аудита перед реальными изменениями.
- Выводит подробный отчёт о каждом изменении (файл, строка, что на что меняется).

```bash
anonymizer src -r --builtin-rules all --preview
```

### C) Реальное удаление (`--apply`)
- Применяет замены к файлам.
- При необходимости делает резервные копии.
- **Без `--apply` никаких изменений в файлах не происходит.**

```bash
anonymizer src -r --builtin-rules all --mode replace --apply
```

**Важно:** флаг `--preview` можно использовать как отдельно, так и вместе с `--apply`. В обоих случаях файлы не изменяются, но в первом случае просто показывается предпросмотр, во втором — тоже предпросмотр (хотя `--apply` обычно означает применение, но в сочетании с `--preview` он игнорируется и выдаётся предупреждение).

## Выбор файлов: директории, рекурсия, паттерны, -d/-dr

### `DIRECTORY ...`
Примеры:

```bash
anonymizer src
anonymizer src tests
anonymizer /path/to/project -r
```

### `-r / --recursive`
Рекурсивный обход “по умолчанию”:

```bash
anonymizer . -r
```

### `-d / --dir` и `-dr / --dir-recursive` (пер‑директория рекурсия)
Позволяет указать режим обхода для конкретной директории:

- `-dr DIR` — DIR обходить рекурсивно
- `-d DIR` — DIR обходить НЕрекурсивно (только верхний уровень)

Пример:
```bash
anonymizer -dr src -d docs -p "*.py" "*.md"
```

Поведение:
- для директорий, перечисленных через `-d/-dr`, режим рекурсии берётся оттуда;
- для остальных директорий действует “дефолт” из `-r` (если не задан — нерекурсивно).

### `-p / --pattern` (несколько паттернов)
Паттерны включения файлов (glob по basename). Поддерживается несколько вариантов передачи:

```bash
anonymizer . -r -p "*.py" "*.js"
anonymizer . -r -p "*.py *.js *.*"
```

Семантика:
- файл включается, если его имя совпадает **хотя бы с одним** паттерном (логика OR).

### `--max-depth`
Ограничение глубины обхода при рекурсивном поиске:

```bash
anonymizer . -r --max-depth 3
```

## Исключения: exclude-dir / exclude-name / exclude-pattern

Исключения применяются на этапе поиска файлов (аналогично `comment_extractor`).

### `-ed / --exclude-dir NAME`
Исключает директории по имени сегмента пути:

```bash
anonymizer . -r -ed venv -ed node_modules -ed __pycache__
```

### `-en / --exclude-name GLOB`
Исключает файлы по имени (basename) через glob:

```bash
anonymizer . -r -en "*.min.js" -en "*.pyc"
```

### `-ep / --exclude-pattern GLOB`
Исключает по пути (паттерн может матчить относительный путь и имя):

```bash
anonymizer . -r -ep "tests/*" -ep "**/migrations/*"
```

## Правила анонимизации

### 8.1 Встроенные правила

Утилита поставляется с набором предопределённых правил, сгруппированных по категориям. Вы можете включить одну или несколько групп через `--builtin-rules`.

**Группы:**
- `credentials` — ключи API (AWS, OpenAI, GitHub, Slack), JWT, пароли, строки подключения к БД, блоки приватных ключей.
- `pii` — персональные данные: email, телефон, IP‑адреса (в том числе локальные).
- `system` — системные пути (например, `C:\Users\...`).
- `all` — все перечисленные группы.

Пример использования:
```bash
anonymizer . -r --builtin-rules credentials,pii
```

### 8.2 Пользовательские правила (YAML/JSON)

Вы можете описать собственные правила в файле и загрузить их через `--rules-file`.
Формат (YAML):
```yaml
- name: My secret pattern
  pattern: 'my_secret_\w+'
  replacement: '[MY_SECRET]'
  mode: replace          # опционально: replace, remove-line, hash
  case_sensitive: true   # по умолчанию true
  whole_word: false      # добавить границы \b
  scope: [".py", ".txt"] # применять только к файлам с этими расширениями
  confidence: high       # для отчёта
  enabled: true
```

JSON-аналог:
```json
[
  {
    "name": "My secret pattern",
    "pattern": "my_secret_\\w+",
    "replacement": "[MY_SECRET]",
    "scope": [".py", ".txt"]
  }
]
```

### 8.3 Правила из `.env` файлов

Если вы укажете один или несколько `.env`‑файлов через `--env-file`, утилита извлечёт все значения переменных (кроме имён) и создаст для каждого значения правило **точного поиска** (с учётом границ слов). Это помогает найти забытые копии секретов в коде.

```bash
anonymizer . -r --env-file .env.prod --env-file .env.local
```

### 8.4 Динамические системные данные

При включённом флаге `--detect-system` (по умолчанию `true`) утилита определяет:
- текущее имя пользователя (`os.getlogin()`),
- домашнюю директорию (`Path.home()`),
- имя хоста (`socket.gethostname()`),
- корень проекта (первая директория из списка входных).

Для каждого из этих значений создаётся правило, заменяющее его на соответствующий плейсхолдер (можно настроить через `--username-placeholder`, `--home-placeholder`, `--hostname-placeholder`, `--project-root-placeholder`).

Пример:
```bash
anonymizer . -r --detect-system --username-placeholder "[USER]" --apply
```
заменит все вхождения текущего логина на `[USER]`.

Чтобы отключить системные правила, используйте:
```bash
anonymizer . -r --no-detect-system
```

## Режимы замены: replace, remove-line, hash

Каждое правило может иметь свой режим обработки, либо задаётся глобальный режим через `--mode`.

### `replace` (по умолчанию)
Заменяет совпадение на указанный плейсхолдер (глобальный `--replacement` или `replacement` в правиле). Поддерживаются обратные ссылки (`\1`, `\2`…).

### `remove-line`
Удаляет всю строку, содержащую совпадение. **Осторожно:** может нарушить синтаксис, если строка содержала не только секрет. Рекомендуется использовать после preview.

### `hash`
Заменяет совпадение на его хеш (SHA256, первые 8 символов) в формате `[HASH:...]`. Полезно, если нужно сохранить связность (одинаковые секреты заменяются одинаково), но не раскрывать исходное значение.

## Jupyter Notebook (`.ipynb`)

Утилита полноценно обрабатывает Jupyter Notebooks. По умолчанию она сканирует **все текстовые поля**:
- исходный код ячеек (`source`),
- выводы ячеек (`outputs`) — все текстовые MIME‑типы (plain, html, markdown, latex, traceback),
- при необходимости метаданные (см. ниже).

Настройки для ноутбуков:
- `--no-scan-notebooks` — полностью пропустить `.ipynb` файлы.
- `--no-scan-outputs` — не сканировать выводы ячеек (только исходный код).
- `--scan-metadata` — включить сканирование метаданных ячеек и ноутбука (по умолчанию выключено, так как там редко бывают секреты, но может быть полезно).

Пример: сканировать только код ячеек, игнорируя выводы:
```bash
anonymizer . -r --no-scan-outputs
```

## Резервные копии (backup)

### Когда создаются бэкапы
Бэкап создаётся **только если одновременно**:
- выполняется реальная анонимизация (флаг `--apply` и **нет** `--preview`);
- действительно есть изменения (файл перезаписан);
- включено сохранение бэкапов: `--keep-backups` или `--backup-dir`.

### `--keep-backups`
Сохранять бэкапы рядом с изменёнными файлами:

```bash
anonymizer . -r --builtin-rules credentials --mode replace --apply --keep-backups
```
Пример:
- `src/main.py` → `src/main.py.bak`

### `--backup-dir PATH`
Сохранять бэкапы в отдельную директорию с сохранением структуры относительно “базы” (первой директории из списка входных директорий):

```bash
anonymizer . -r --builtin-rules all --apply --backup-dir .backups
```
Пример:
- `src/main.py` → `.backups/src/main.py.bak`

### `--overwrite-backups`
По умолчанию, если бэкап уже существует — создаётся версия `.bak.1`, `.bak.2` и т.д. Чтобы всегда держать только последний бэкап:

```bash
anonymizer . -r --backup-dir .backups --overwrite-backups
```

## Экспорт результатов (совпадений)

### `--export-matches PATH`
Экспортирует все найденные совпадения. Формат зависит от расширения:

- `.txt` — текстовый отчёт с перечислением каждого совпадения.
- `.json` — структурированный JSON с метаданными.
- `.jsonl` — JSON Lines (по одному объекту на строку).

Примеры:

```bash
anonymizer . -r --builtin-rules all --export-matches report.json
anonymizer . -r --builtin-rules all --export-matches report.jsonl
anonymizer . -r --builtin-rules all --export-matches report.txt
```

### Структура JSON (пример)
```json
{
  "generated_at": "2026-02-21 10:30:00",
  "total_matches": 5,
  "matches": [
    {
      "file": "/home/[USER]/project/src/config.py",
      "relative_path": "src/config.py",
      "rule_name": "AWS Access Key",
      "matched_text": "AKIAIOSFODNN7EXAMPLE",
      "replacement_text": "[AWS_KEY]",
      "line": 42,
      "column": 10,
      "confidence": "high",
      "cell_index": null,
      "field": null
    }
  ]
}
```

Для ноутбуков поля `cell_index` и `field` заполняются.

## Логи, подробность и split streams

### `-o / --output FILE` и `--log-file FILE`
- `--output` — файл логов (диагностические сообщения).
- `--log-file` — алиас для `--output`.

```bash
anonymizer . -r -o run.log
```

### `-v / --verbose`
Более подробный вывод (debug‑информация):

```bash
anonymizer . -r -v
```

### `--split-streams` (для GUI/обёрток)
Разделяет “основной вывод” и диагностику:

- **stdout**: краткий отчёт в конце (`OK: matches=... modified=... files=...`)
- **stderr**: прогресс, предупреждения, ошибки, найденные совпадения (если не указан `--export-matches`).

```bash
anonymizer . -r --split-streams
```

## Ограничения и важные замечания

1. **Регулярные выражения** — не всегда точны. Могут быть ложные срабатывания. Всегда используйте `--preview` перед реальными изменениями.
2. **`remove-line` может сломать код** — применяйте только если уверены, что строка целиком содержит только секрет (или в проектах, где синтаксис не важен, например, в логах).
3. **Jupyter Notebook** — при замене в выводах ячеек может нарушиться цветовое оформление ANSI, но это безопасно.
4. **Системные правила** заменяют **все** вхождения имени пользователя, даже если оно является частью другого слова (если не настроены границы слов). При необходимости используйте более точные пользовательские правила.
5. **Производительность** — на больших проектах может работать медленно из-за большого количества regex. Рекомендуется использовать `-p` для сужения круга файлов.

## Готовые сценарии

### 1) “Просканировать проект и посмотреть, какие секреты есть”
```bash
anonymizer . -r -ig --builtin-rules all --preview
```

### 2) Заменить все AWS‑ключи на `[AWS_KEY]` с созданием бэкапов
```bash
anonymizer . -r -p "*.py" "*.yml" --builtin-rules credentials --mode replace --apply --keep-backups
```

### 3) Удалить строки, содержащие пароли, из логов
```bash
anonymizer logs/ -r -p "*.log" --builtin-rules credentials --mode remove-line --preview
# после проверки:
anonymizer logs/ -r -p "*.log" --builtin-rules credentials --mode remove-line --apply --backup-dir .log-backups
```

### 4) Обезличить ноутбуки, заменив email‑адреса
```bash
anonymizer notebooks/ -r --builtin-rules pii --mode replace --replacement "[EMAIL]" --scan-outputs --apply
```

### 5) Использовать свои правила + .env + системные данные
```bash
anonymizer . -r \
  --rules-file my-rules.yaml \
  --env-file .env \
  --detect-system \
  --mode hash \
  --export-matches report.json
```

### 6) Интеграция в pre‑commit хук (только проверка, без изменений)
```yaml
# .pre-commit-config.yaml
- repo: local
  hooks:
    - id: anonymizer-check
      name: Check for secrets
      entry: anonymizer . -r --builtin-rules all --preview
      language: system
      pass_filenames: false
```

## Частые проблемы

### “Почему ничего не нашлось, хотя я знаю, что секреты есть?”
- Проверьте, что файлы попадают под `-p` (или вообще без паттерна).
- Убедитесь, что не включены исключения (`-ed`, `-en`, `-ep`), которые могли скрыть нужные файлы.
- Возможно, правило не покрывает ваш случай — попробуйте `--builtin-rules all` или добавьте пользовательское правило.

### “Я заменил секреты, но файлы не изменились (preview работает, реальный запуск — нет)”
- Проверьте, указан ли флаг `--apply` (без него изменения не применяются).
- Убедитесь, что не указан `--preview` одновременно с `--apply` (тогда будет предпросмотр, а не реальное изменение).
- Посмотрите логи (`-v`): возможно, произошла ошибка при записи, и бэкап был восстановлен.

### “Бэкапы не создаются”
- Проверьте, что вы используете `--keep-backups` или `--backup-dir`.
- Убедитесь, что файлы действительно были изменены (иначе бэкап не нужен).

### “Я использую `--remove-line`, но строки не удаляются”
- Проверьте режим в правиле: может быть, используется глобальный `--mode replace`, а в правиле не указан `mode: remove-line`.
- Убедитесь, что совпадение находится: preview должен показать строки, помеченные к удалению.

### “Очень медленно работает”
- Уменьшите область поиска с помощью `-p` и исключений.
- Отключите сканирование ноутбуков, если они не нужны (`--no-scan-notebooks`).
- Рассмотрите возможность использования `--no-cache`? (кэш обычно ускоряет, но если файлы постоянно меняются, может быть наоборот). Попробуйте без кэша.

### “YAML‑правила не загружаются”
- Установите PyYAML: `pip install pyyaml`.
- Проверьте синтаксис файла (можно использовать онлайн‑валидатор).
